## 0. 约定

- 来源标记：**【定】** 用户定下的机制；**【临时】** 用户提的平衡尝试，还要再看；**[用]** 用户定；**[原]** 原版规则（美少女梦工厂 2；见 `original/SUMMARY.md`、`original/data/tables/`）；**[推]** 推定，理由见 `DESIGN_NOTES.md` 同编号条目（如 [推N3]）。
- 所有名字都是占位，用普通词。标 **占位** 的数值和内容等用户给设定后替换。
- 随机函数：`r(a,b)` 取 a..b 的整数（含两端）；`r0(n)` 取 0..n；`r1(n)` 取 1..n。除法向零截断 [原]。
- 属性加减后都夹在各自范围内。
- 金钱单位是 1920 年代的美元，全部为整数 [用]。
- 本文只写现在的规则。和 `data/new/*.json` 不一致时以 JSON 为准。
- **现在事件全关**（`events.json` 的 `enabled: false`，包括外出事件、月末事件、时代事件），瓦伦不去世（`valen_death: false`）[用]。第 11 节和别处写的事件规则在开关打开时才生效。临时换角和抢角另有开关 `role_events`，现在开着（用户要测试镜平衡）。

#### 2.1.1 刻度和档位【定】[用]

基础属性的量级差很多（义气 200 已经算高，体力 900 不稀奇），事件和判定不直接读原始数字。

- 每项基础属性有一个除数，换算成 0–100 的刻度：`刻度 = min(100, 原始值 / 除数)`。除数（占位，之后按机器人报告的分布定）：体力 8、教育 3、义气 2.5、相貌 5、自律 3、犯罪 4、疲劳 8（`stats.json` 的 `scale.div10`，存的是除数 ×10）。
- 技能本来就是 0–100，刻度 = 显示值。名气保留自己的五档（2.5），不并进来。
- 档位一套，所有属性通用（按刻度）：0–24 低，25–49 中，50–74 高，75+ 很高。
- 事件条件写档位（`tier.loyalty >= high`），要细的时候写刻度（`scale.loyalty >= 60`），不写原始数字。调平衡只改除数，事件、判定、标签跟着走。
- 例外：状态标签可以用原始数字（身材走样是相貌显示值 <60）。
- 自律、犯罪的分工见 [推N49]。

## 4. 月流程与结算顺序

每月按下面顺序执行 [原骨架][推N17]：

1. **月初**
   1. 扣生活费（5.7），扣到 0 为止。
   2. 选片月（6.1）：出选片板，可试镜（6、7）。
   3. 自由操作，不占日程：选生活方式、物品和装备、看“下次选片”；和 Sil 谈话、戒毒、放消息在家里，买药在地图上的毒贩（5.0）。
   4. 每一旬在地图上选一个地点、一项日程（5.0）；被拍摄锁定的旬自动去片场。
2. **逐旬**（上、中、下）
   1. 逐日执行日程；每天结算数值，然后过一天。
   2. 外出的旬：在旬中触发该去处的一个事件（5.5.2）。
   3. 生日当天插入生日事件。
   4. 旬末检查：临时换角、抢角（11.1）。
3. **月末事件**：按 11.2 表的顺序逐条判定，每月最多触发 2 个，其余顺延到下月再判 [推N17]。
4. **月结**
   1. 生活方式的体力效果。
   2. 上映结算（8）。
   3. 名气衰减（2.5）。
   4. 算生病指数，更新状态（10）。
   5. 重病计数与倒下判定。
   6. 恋爱状态计时。
   7. 12 月：年度大事（12.1）。
   8. 时代事件（11.3）。
   9. 1929-12：进入结局判定（15）。

## 7. 试镜

结构 [用]。

### 7.1 流程

1. 报名：名气 ≥ 门槛。
2. 双方各自秘密组 5 张牌。
3. 同时亮牌：双方看到对方 5 张牌的颜色和点数；同时揭晓场风（按角色的场风概率抽一色）。
4. 最多 5 轮，每轮双方同时出一张没出过的牌，比有效点数。
5. 先赢 3 轮的一方胜 [推N30]。
6. 大片连打 2 场，对手不同，第二场重新组牌、重新抽场风；两场都赢才算赢 [推N31]。

### 7.2 牌

- 四色 = 四条路，牌没有特殊效果 [用]。
- 玩家自己选 5 张的颜色 [用]。同色第 k 张（k 从 0 起）点数 = `max(0, 该路等级 − k)` [用]。

### 7.3 有效点数

```
v = 点数
if 牌色 == 场风: v *= 1.3            # [用：先 1.3，待测]
if 我克对方 且 对方牌色 != 场风: v *= 1.3，对方 v *= 0.8   # [用]
```

- 克制环：硬汉克情人，情人克文化，文化克手腕，手腕克硬汉；相对的两色互不相干 [用]。
- 场风色不受克制（双方系数都不生效）[用]。
- 比较：大者胜该轮；相等则名气高者胜；仍相等对手胜 [推N32]。

### 7.4 结果 [推N33]

| 比分 | 结果 |
|---|---|
| 3:0 | 拿到角色；“被导演记住”：该角色的导演下一次出现时，玩家主色的场风概率 +10 个百分点（从最高的其他色里扣） |
| 3:1、3:2 | 拿到角色 |
| 2:3 | 惜败：可选同片配角（拍摄旬数 −1，最少 1；片酬 ×0.4；上映名气和声望修正 ×0.3；标签照记，不记“低成本制作”） |
| 1:3 | 落选 |
| 0:3 | 演砸：名气 −5%；20% 上报（曝光，名气再 −5%） |

大片第一场输按上表结算；第一场赢、第二场输一律按惜败。

### 7.5 对手的组牌 [推N34][用：副色防克制]

每个对手有主色张数 `k`（3、4 或 5）。主色 = `等级 × (1 + 0.3 × 该色场风概率)` 最大的颜色；其余 `5−k` 张取主色的“克星的克星”：克主色的那一色被谁克，就带谁。情人带手腕，硬汉带文化，文化带硬汉，手腕带情人。对手不傻，会防着被克的颜色抢角色。

### 7.6 对手的出牌习惯 [用][推N35]

每轮 80% 按习惯出，20% 在剩余牌里均匀随机。“大小”按对当前场风的有效点数（不计克制）排。

| 习惯 | 规则 |
|---|---|
| 抢先 | 从大到小出 |
| 压轴 | 从小到大出 |
| 开门红 | 第一轮出最大，之后从小到大 |
| 跟牌 | 第一轮出中间那张；之后出能赢过玩家上一轮那张牌的最小牌，没有就出最小 |
| 看比分 | 落后或平手时出最大，领先时出最小 |
| 随性 | 始终均匀随机 |

情报：
- 和某个对手交手满 2 次，或洞悉 ≥60：组牌界面显示他的习惯和主色张数 `k`。
- 洞悉 ≥80：组牌前排除场风概率最低的一色。
- Duv 的告密（6.5）：显示某个角色完整的场风概率。

## 8. 上映

### 8.1 时间

最后一个拍摄日所在月之后第 2 个月的月结结算 [推N21]。

### 8.2 票房分

```
S = B × P × F × T
B: 小片 40 / 中片 100 / 大片 250
P: 拍摄表现（5.6）
F: 契合 = 0.6 + 0.4 × 平均( min(属性或技能/目标, 1.5) )，范围 0.6–1.2
T: 标签熟悉 = 1 + 0.03 × min(该角色各标签已有计数之和, 5)
```

结算：
- 名气 += `S × 0.3`（取整）。
- 分红 = `S × 2`。
- 该角色场风概率最高的那条路，声望修正按片子得分 `X = S / B` 分四段、按片子大小查 `roles.json` 的 `release.rep_table` [用]。配角乘 `release_pct`。修正可以是负数：

| 段 | 条件 | 声望修正 小/中/大 |
|---|---|---|
| 大卖 `hit` | `X ≥ 1.55`（`hit_pct` 155） | +10 / +20 / +64 |
| 正常 `normal` | `1.0 ≤ X < 1.55`（`fail_pct` 100） | +4 / +8 / +16 |
| 不行 `poor` | `0.7 ≤ X < 1.0` | −4 / −8 / −16 |
| 惨败 `flop` | `X < 0.7`（`flop_pct` 70） | −10 / −20 / −64 |

  大卖要 P、F、T 三项都高（例如 P 1.2 × F 1.2 × T 1.0）。用户的意图：大片是大赌注，成了非常成功，砸了很难翻身。
- 惨败：名气只加一半。
- 角色的每个标签计数 +1。
- 低成本计数：主演小片 +1，主演中片 −1，主演大片 −2，最低 0（8.4）。
- 以上各项 [推N36]。

### 8.3 有声片

有声角色若谈吐显示值 < 谈吐线：`S × 0.6`，并触发一次“口音”事件（11.2）[推N3]。

### 8.4 戏路标签（17 个）[用][推N37][推N56]

内容标签 16 个：西部、动作冒险、战争、古装、浪漫、异国情人、歌舞、喜剧、悲情、文艺、宗教、贵族、反派、犯罪、恐怖、地下片。
制作标签 1 个：低成本制作。

- 定型：某内容标签计数 ≥3 [推N59]。该标签角色 T 取满，其余标签的角色 `S × 0.9`。
- 低成本定型：低成本计数 ≥4，成为“低成本演员”。期间大片的名气门槛 +50；小片的 T 取满；杂志和来信换一套说法。计数降到 3 以下即解除。
- 无法定义：有计数的内容标签 ≥6 种且没有一个 ≥3。用于结局和杂志文案。
- 玩家看不到计数，只从杂志和来信的文字感知 [用]。

## 11. 事件

所有事件：条件满足后按概率触发 [原]。

### 11.0 事件里的判定 [用][推N50]

事件选项可以带一个判定，两种写法：

- 门槛：`[属性或技能, ">=", 值]`，同条件语法（16）。
- 掷骰（d100）[用]：`{判定: 技能或基础属性, 难度: n}`。`成功率 = 刻度值 − 难度`，夹在 5–95（`stats.json` 的 `check`，占位）：永远不能 100% 成功，否则骰子没有意义。掷 1–100，不大于成功率就成功。成功率在掷之前就能算出来（`Rules.check_pct`），以后界面先显示成功率再掷。
